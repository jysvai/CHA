# 00 — 왜

**English: [00-why.md](../en/00-why.md)**

---

## 막으려는 실패

코딩 에이전트는 자기 코드의 검토자로서 **고를 수 있는 것 중 제일 못 믿을 검토자**입니다.

이유는 성능이 아닙니다. 위치입니다.

- 그 코드를 제가 썼습니다. 어떤 입력을 고려했는지 **기억하고** 있고, 그 기억이 코드를 대신 읽어 줍니다.
- 같은 주석을 읽었습니다. 주석이 「이 함수는 알 수 없는 줄을 성공으로 안 친다」 고 말하면, 코드를 보면서도 그 문장이 먼저 들어옵니다.
- 같은 자리가 안 보입니다. 짤 때 안 떠오른 경계값은 읽을 때도 안 떠오릅니다.

여기에 하나 더 붙습니다. **확신이 없을 때 조용해지지 않습니다.** 매끄럽고 자신 있는 틀린 답을 냅니다. 사람 검토자는 애매하면 「잘 모르겠는데」 라고 말하지만, 모델은 그 자리에서 그럴듯한 문장을 만듭니다. 그 문장에는 「나는 이걸 안 돌려 봤다」 는 표시가 안 붙습니다.

이게 CHA 가 막으려는 실패 하나입니다.

## 흔한 처방이 왜 안 듣나

### 「네 diff 를 검토해 봐」

같은 모델 · 같은 맥락 · 같은 사각지대. 방금 그 코드를 쓴 확률 분포가 그대로 남아 있는 상태에서 「이거 틀렸니」 를 묻는 것입니다. 틀렸다고 판단할 근거가 있었으면 애초에 그렇게 안 썼습니다.

### 같은 모델로 한 번 더

이게 제일 많이 쓰이고 제일 설득력 있어 보이는 처방인데, **오류가 상관되어 있어서** 안 듣습니다.

검토가 값이 있는 건 두 검토자의 실수가 **서로 독립**일 때입니다. 둘 다 놓칠 확률이 각자 놓칠 확률의 곱이 되니까요. 같은 모델을 두 번 돌리면 그 곱이 성립하지 않습니다. 첫 번째가 놓친 것은 두 번째도 거의 확실히 놓칩니다 — 같은 가중치가 같은 토큰을 보고 같은 판단을 합니다.

실제로 관찰되는 건 더 나쁩니다. **자기 말에 동의합니다.** 첫 답이 맥락에 들어 있으면 두 번째 판은 검토가 아니라 추인이 됩니다.

### 더 센 린터

린터는 **모양**을 봅니다. **거짓말**은 구조적으로 못 봅니다.

```js
// ok 없는 줄은 성공으로 안 친다.
if (!줄.includes('fail')) 성공++;
```

린터에게 이 코드는 흠 없습니다. 문법도 맞고, 안 쓰는 변수도 없고, 타입도 맞습니다. 그런데 주석과 코드가 서로 다른 말을 합니다. 어느 쪽이 버그인지 정하려면 **의도**를 알아야 하고, 그건 파서가 가진 정보가 아닙니다.

린터가 못 보는 것을 갈래로 적으면 이렇습니다.

- 주석·문서·이름이 코드와 어긋난 것 (의미의 문제)
- 정규식이 **실제로 들어오는 값**에 안 맞는 것 (데이터의 문제)
- 검사 이름이 약속한 것보다 검사 본문이 적게 보는 것 (약속의 문제)
- 봉인을 **늦게** 확인해서 이미 나간 뒤인 것 (순서의 문제)

넷 다 문법은 멀쩡합니다.

### 검사를 더

검사가 많으면 좋습니다. 그런데 **검사가 초록인 것은 증거가 아닙니다.**

`npm test` 가 초록이라는 건 「아무도 뭘 망가뜨리지 않았다」 는 뜻입니다. 「망가뜨리면 뭔가 알아챈다」 는 뜻이 아닙니다. 이 둘은 밖에서 보면 똑같이 생겼고, 값은 정반대입니다.

아무것도 안 재는 검사도 초록입니다. 이름이 `「셈이 숫자가 아니면 안 받는다」` 인데 안을 열어 보면 `'many'` 하나만 물어보는 검사 — 이것도 초록입니다. 통과 개수에 1 을 보탭니다. 아무도 모릅니다.

그래서 CHA 는 검사를 세지 않고 **검사를 잽니다**. 고친 줄을 일부러 망가뜨려서, 그 줄을 지킨다는 검사가 빨개지는지 봅니다. 안 빨개지면 그 검사는 이름만 그 줄을 지킵니다. → [07 — 어긋내기](07-어긋내기.md)

## 그래서 플랫폼째 가른다

상관된 오류를 끊는 방법은 하나뿐입니다. **다른 곳에서 온 검토자를 쓰는 것.**

다른 플랫폼의 모델은 학습 자료가 다르고, 자료를 자르는 방식이 다르고, 조정 방식이 다릅니다. 그래서 「무엇이 정상으로 보이는가」 의 집합이 다릅니다. 더 똑똑한 검토자를 사는 게 아니라 — 그럴 수도 있고 아닐 수도 있습니다 — **다른 사각지대를 사는 것**입니다.

붙는 규칙 셋은 전부 이 하나에서 나옵니다.

- **읽기 전용.** 검토자가 고칠 수 있으면 쓰는 곳이 둘이 됩니다. 각자의 수정은 각자 맞는데 둘이 겹친 자리는 아무도 안 읽습니다. 잰 회차에서 나온 **반만 붙은 고침 3건**이 정확히 이 모양이었습니다 — 머리말은 고쳐진 동작을 설명하는데, 부르는 자리 둘 중 하나만 그렇게 움직입니다.
- **모델 고정.** `latest` 는 말없이 바뀝니다. 바뀌면 회차와 회차 사이의 숫자가 뜻을 잃습니다.
- **한 판씩.** 병렬로 세 판을 보냈다가 개인 한도가 **4분 만에 비었고 답 셋을 전부 잃었습니다.** 각 판이 제 재시도 루프를 따로 돌렸기 때문입니다.

자세한 것은 [05 — 2차 눈](05-2차눈.md).

## 그리고 「돌려 본다」

플랫폼을 갈라도 지적이 참인지는 아직 모릅니다. 다른 사각지대는 다른 오답도 같이 가져옵니다.

거르개는 하나뿐입니다.

> **주장은 「거짓이었다면 다르게 움직였을 무언가」 를 돌려 봤을 때 참이 된다.**

잰 회차의 숫자입니다.

| | |
|---|---|
| 올라온 지적 | **57건** |
| 실행으로 확인된 참 | **22건** |
| 실제로 고친 자리 | **19곳** |
| 못 잼으로 적은 것 | **4건** |

열에 여섯이 그럴듯하고 틀렸습니다. 그리고 읽기만 해서는 어느 쪽이 어느 쪽인지 **알 수 없었습니다** — 틀린 쪽도 근거가 붙어 있었고 파일과 줄번호가 맞았고 문장이 매끄러웠습니다.

만약 안 돌려 보고 다 고쳤다면 57곳을 건드렸을 것이고, 그중 **35곳은 멀쩡한 코드**입니다. 멀쩡한 코드를 고치는 것은 공짜가 아닙니다. 한 번마다 되던 것을 망가뜨릴 기회입니다.

이게 CHA 를 떠받치는 문장의 전부입니다. 나머지 여덟 걸음은 이 한 걸음을 돌릴 수 있게 만드는 장치입니다.

## 다섯 갈래 결함

브리핑마다 이 다섯을 붙입니다. 여섯 회차를 살아남은 갈래입니다. 셋 다 해당합니다 — 린터가 못 보고, 같은 모델이 이름 못 붙이고, 초록 검사 뒤에 숨습니다.

### 1. 실제 입력에 절대 안 맞는 규칙

```
/(1b|2b|3b)/  →  "qwen2.5-coder:32b"
```

32B 모델을 「작은 모델」로 셌습니다. `32b` 안에 `2b` 가 들어 있어서요. 규칙은 돌아갔고 예외도 안 났습니다. 그냥 계속 틀린 답을 냈습니다.

### 2. 조용한 실패

```js
try { 시트읽기(x); } catch { continue; }
```

못 읽은 시트를 건너뛰고, 결과 문장은 「다 읽었습니다」 였습니다. 실패가 성공과 똑같이 생겼습니다.

### 3. 안 지키는 검사

이름은 `「셈이 숫자가 아니면 안 받는다」`. 본문은 `'many'` 하나만 물어봅니다. `'3'` · `null` · `true` · `[]` 가 전부 그냥 지났습니다. 검사는 있고, 초록이고, 아무것도 안 지킵니다.

### 4. 주석과 코드의 모순

머리말은 「`ok` 없는 줄은 성공으로 안 친다」. 코드는 성공으로 셌습니다. 그래서 보고되는 실패율이 실제보다 낮았습니다 — 사람이 보는 숫자가 틀렸습니다.

둘 중 하나가 버그인데, **어느 쪽인지 정하는 건 읽어서는 안 됩니다.** 돌려 봐야 합니다.

### 5. 신뢰 경계 누수

`--offline` 봉인을 **바깥 주소를 세 번 두드린 뒤에** 봤습니다. 열쇠까지 실어 보낸 뒤에요. 봉인은 있었고, 코드에 적혀 있었고, 늦었습니다.

## 거짓 경고도 결함이다

마지막 규칙 하나.

**없는 고장을 말하는 코드는 조용한 코드와 값이 같습니다.**

한 번 거짓으로 빨개진 경고는 다음부터 안 읽힙니다. 안 읽히는 경고는 없는 경고고, 없는 경고 자리에 진짜 고장이 오면 조용히 지납니다. 그래서 「과하게 경고하는 쪽이 안전하다」 는 말은 틀렸습니다 — 그건 경고 장치를 스스로 끄는 방법입니다.

CHA 에서 거짓 경고는 결함으로 셉니다. 지적으로 올리고, 판정하고, 고치고, 어긋을 박습니다. 다른 결함과 똑같이.
