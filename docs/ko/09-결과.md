# 09 — 결과

**English: [09-results.md](../en/09-results.md)**

여기 있는 숫자는 전부 한 저장소에서 잰 것입니다 — `deel`, 의존성 0 짜리 Node CLI 코딩 에이전트. 39회차를 돌렸습니다.

**먼저 말해 둘 것.** 이것은 벤치마크가 아닙니다. 저장소 하나, 2차 눈 짝 하나, 사람 하나입니다. 이 숫자가 보이는 것은 「이 루프가 진짜 결함을 찾아낸다」 는 것뿐이고, 「다른 저장소에서 몇 퍼센트가 나온다」 는 것이 아닙니다. 아래 모든 숫자에 **무엇을 뜻하지 않는가**를 같이 붙인 이유가 이것입니다.

---

## 잰 것

### 대상

| | |
|---|---|
| 소스 | **171 파일 · 77,607 줄** |
| 검사 | **154 파일 · 75,499 줄** |
| 커밋 | **434개** |

검사 줄 수가 소스 줄 수와 거의 같습니다. **이것은 좋은 신호가 아닙니다.** 검사가 많다는 것이지, 검사가 무언가를 지킨다는 것이 아닙니다. 그 구별은 전수 어긋내기에서만 나옵니다 — 아래에 있습니다.

### 마지막 관문

```
검사   12,596 통과 / 0 실패 / 1 건너뜀 — 파일 156/156 정상 종료
검사기 OK · 167 파일 · 배포 파일 170개 전부 LF
문서   62쪽 · 깨진 링크 0
```

**12,596 통과가 뜻하는 것:** 지금 짜 놓은 단언 중에 코드와 어긋나는 것이 하나도 없다.

**뜻하지 않는 것:** 코드가 맞다. 그것과는 아무 상관이 없습니다. 단언이 아무것도 안 물어보면 그것도 통과로 셉니다. 「이 검사가 무언가를 지키는가」 를 재는 것은 통과 수가 아니라 어긋내기입니다.

**파일 156/156 이 뜻하는 것:** 통과 수가 「검사 파일이 단언 전에 죽어서」 줄어든 것이 아니다. 이 줄이 없으면 앞 줄을 믿을 수 없습니다. 까닭은 [08 — 관문과 기록](08-관문과기록.md)에 있습니다.

**1 건너뜀이 뜻하는 것:** 아직 안 잰 것이 하나 있다. 0 이 아닙니다. 통과 칸에 넣지 않습니다.

### 어긋 / 변이

| | |
|---|---|
| 등록된 어긋 | **1,179개** · 소스 138 파일 / 검사 119 파일에 걸침 |
| 마지막 전수 | **1,149개 · 2시간 46분** |
| 결과 | 잡음 **1,125** · 샜음 **2** · 못 잼 **22** |

**1,125 잡음이 뜻하는 것:** 일부러 망가뜨린 자리 1,125곳에서, 짝지어 둔 검사가 빨개졌다.

**뜻하지 않는 것:** 코드의 97.9% 가 지켜진다. 그런 비율이 아닙니다. 잰 것은 **내가 적어 놓은 1,149개의 특정한 파손**이고, 적지 않은 파손은 재지 않았습니다. 어긋 목록이 곧 「내가 재기로 한 범위」이고, 그 범위 밖은 이 숫자가 아무 말도 하지 않습니다.

**1,179 − 1,149 = 30.** 마지막 전수 뒤에 붙은, 아직 전수로 안 돌린 어긋입니다. 이것도 적어 둡니다. 「전부 돌렸다」 와 「그때 있던 것을 전부 돌렸다」 는 다른 말입니다.

**2 샜음 · 22 못 잼 — 이 스물넷이 발견입니다.**

- **샜음 2**: 일부러 망가뜨렸는데 아무 검사도 안 잡았습니다. 그 두 줄은 지금 아무도 안 지키고 있고, 다음 사람이 지워도 빨간 것이 안 뜹니다.
- **못 잼 22**: 앵커가 낡아서 **아무것도 안 재고 있던** 어긋입니다. 목록에 이름이 있고, 개수에 세어지고, 전수 총계를 건강해 보이게 만들고 있었습니다.

둘 중 **뒤엣것이 더 위험합니다.** 샌 어긋은 빨간 화면으로 보입니다. 못 잰 어긋은 **빨간 실행에서도 초록 실행에서도 안 보입니다.** 이것이 CHA 가 사냥하는 결함 갈래가, CHA 의 도구 안에 살고 있던 경우입니다. `tools/mutate.mjs` 가 못 잼을 **실패로 세는** 이유입니다.

### 2차 눈

| | |
|---|---|
| 돌린 관문 | **39회** |
| 보낸 브리핑 | **39판** |
| 올라온 지적 | **57건** |
| 실행으로 확인된 참 | **22건** |
| 실제로 고친 자리 | **19곳** |
| 못 잼으로 적은 것 | **4건** |

**57 → 22 가 뜻하는 것:** 자신 있게 올라온 지적 열에 여섯이 틀렸다. 읽기만 해서는 어느 쪽이 어느 쪽인지 알 수 없었습니다.

**뜻하지 않는 것:** 이 모델의 일반 정확도가 39% 다. 아닙니다. 이것은 **이 2차 눈 · 이 저장소 · 이 브리핑 크기** 에서 나온 값입니다. 다른 저장소에서는 다른 숫자가 나옵니다.

**뜻하는 것 하나 더:** 그럴듯함으로 움직였으면 **멀쩡한 코드에 35번 손을 댔을 것**입니다. 그 35번은 각각 잘 돌던 것을 깨뜨릴 기회입니다.

참 22건 중 고침으로 이어진 것이 19곳입니다. 나머지는 이미 다른 고침이 덮었거나, 같은 자리를 가리켰습니다.

### 기록

| | |
|---|---|
| 누적 기록 | **2,745줄** |

보태기만 했습니다. 39회차 동안 한 번도 줄어든 적이 없습니다. 거짓으로 판명난 지적도, 되돌린 고침도, 샌 어긋도, 못 잰 넷도 그대로 있습니다. 까닭은 [08 — 관문과 기록](08-관문과기록.md)에 있습니다.

## 다섯 갈래 결함 — 실제로 나온 것

브리핑마다 붙이는 다섯 갈래는 책상에서 고른 것이 아니라 **회차를 거듭하며 살아남은** 것입니다. 린터가 못 보고, 같은 모델이 이름 붙이지 못한 갈래입니다.

아래 코드 조각은 **모양을 재구성한 것**이지 그대로 뜬 diff 가 아닙니다. 실제 자리와 줄 번호는 대상 저장소의 기록에 있습니다.

### 1. 실제 입력에 절대 안 맞는 규칙

**약속한 것:** 작은 모델을 걸러 낸다.

**한 것:** `qwen2.5-coder:32b` — 32B 모델 — 을 「너무 작음」으로 셌습니다.

```js
// 모양 재구성
const 작은가 = /(1b|2b|3b)/.test(이름);
```

`32b` 안에 `2b` 가 들어 있습니다. 규칙은 이름의 **아무 자리**나 봤고, 뒤에서부터 봐야 했습니다.

**사람이 치른 값:** 쓸 수 있는 제일 큰 모델이 목록에서 조용히 빠졌습니다. 오류도 경고도 없이, 그냥 안 보였습니다.

**어떻게 쟀나:** 그 정규식을 실제 모델 이름에 대고 한 줄로 돌려서 출력을 봤습니다.

### 2. 조용한 실패

**약속한 것:** 시트를 전부 읽는다.

**한 것:** 못 읽은 시트를 건너뛰고, 결과는 「다 읽었습니다」 였습니다.

```js
// 모양 재구성
for (const 시트 of 시트들) {
  try { 읽기(시트); } catch { continue; }
}
```

`continue` 가 실패를 삼켰습니다. 개수도 안 줄었고, 로그도 안 남았습니다.

**사람이 치른 값:** 빠진 데이터를 「없는 데이터」로 읽었습니다. 틀린 답이 아니라 **틀린 줄 모르는 답**이 나왔습니다.

**어떻게 쟀나:** 못 읽을 시트를 하나 만들어 넣고, 결과가 여전히 「다 읽었다」고 하는지 봤습니다.

### 3. 안 지키는 검사

**약속한 것:** 검사 이름 — 「셈이 숫자가 아니면 안 받는다」.

**한 것:** `'many'` 하나만 물어봤습니다. `'3'`, `null`, `true`, `[]` 가 전부 그냥 지났습니다.

**사람이 치른 값:** 그 자리는 **검사가 있는 자리**로 세어졌습니다. 아무도 다시 안 봤습니다. 이 갈래가 제일 비싼 까닭이 이것입니다 — 구멍이 있는 것이 아니라, **구멍 위에 「지킴」 이라고 적힌 표지가** 있습니다.

**어떻게 쟀나:** 그 검사가 이름 붙인 줄을 망가뜨리고 검사를 돌렸습니다. 그대로 통과했습니다. [어긋내기](07-어긋내기.md)가 하는 일 그대로입니다.

### 4. 주석과 코드의 모순

**약속한 것:** 머리말 — 「`ok` 없는 줄은 성공으로 안 친다」.

**한 것:** 성공으로 셌습니다.

**사람이 치른 값:** **실패율이 실제보다 낮게** 나왔습니다. 숫자를 보고 「괜찮네」 하고 넘어갔는데, 실제로는 안 괜찮았습니다. 틀린 숫자보다 **틀린 방향으로 틀린 숫자**가 비쌉니다.

**어떻게 쟀나:** `ok` 없는 줄을 하나 먹이고 세는 값을 찍었습니다. 주석과 코드 둘 중 하나는 반드시 버그입니다. 어느 쪽인지는 실행이 정합니다.

### 5. 신뢰 경계 누수

**약속한 것:** `--offline` 이면 바깥으로 안 나간다.

**한 것:** `--offline` 을 **바깥 주소를 세 번 두드린 뒤에** 봤습니다. 열쇠까지 실어서.

**사람이 치른 값:** 「오프라인」 이라고 켜 놓은 사람의 열쇠가 세 번 나갔습니다. 화면에는 오프라인이라고 적혀 있었습니다.

**어떻게 쟀나:** 연결을 가짜로 세워 두고, **보내기 직전에 무엇이 실려 있었는지** 찍었습니다. 「읽어 보니 괜찮아 보인다」 로는 절대 안 나올 결론입니다.

## 못 잰 넷

마지막 회차에 올라온 지적 중 넷은 **이 기계에서 돌릴 수가 없었습니다.**

| 지적 | 왜 못 재나 |
|---|---|
| 유닉스 전용 자식 프로세스 거두기 경로 | 호스트가 윈도 |
| 경로 A | 이 기계에 안 깔린 소프트웨어가 있어야 함 |
| 경로 B | 이 기계에 안 깔린 소프트웨어가 있어야 함 |
| CLI 인자 치환 규약 | 양쪽으로 읽힘 — 두 해석을 가르는 입력이 없음 |

**넷 다 「못 잼」 으로 적었지, 「거짓」 으로 적지 않았습니다.**

거짓으로 적으면 그 회차 성적표가 깨끗해집니다. 그리고 그 깨끗함은 거짓말입니다. 못 잼으로 적어 둔 덕분에 나머지 숫자가 뜻을 가집니다 — 22건 참, 4건 못 잼이라고 적힌 회차는, 「57건 중 22건이 참이고 나머지는 다 아니었다」 고 적힌 회차보다 **정확히 4건만큼 더 정직합니다.**
