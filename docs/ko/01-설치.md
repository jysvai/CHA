## 1. 플러그인 깔기

```
/plugin marketplace add jysvai/CHA
/plugin install cha@cha
```

로컬 클론으로 써도 됩니다.

```bash
git clone https://github.com/jysvai/CHA ~/CHA
```

```
/plugin marketplace add ~/CHA
/plugin install cha@cha
```

들어오는 것: 명령 10개 · 스킬 6개 · 에이전트 3개 · `tools/` 안의 도구 · `hooks/hooks.json` 의 훅 하나.

---

## 2. 저장소에 깔기

검수할 저장소에서:

```
/cha-init
```

만드는 것:

```
.cha/
  config.json      # 관문 명령 · 2차 눈 명령 · 브리핑 크기 한도
  record.md        # 누적 기록 — 보태기만, 절대 안 지움
  mutants.json     # 어긋 목록
  briefings/       # 만들어진 브리핑, 조각마다 하나
  answers/         # 2차 눈 답, 태그마다 하나
```

씨앗은 `templates/` 에서 옵니다 — `config.json` · `record.md` · `mutants.json`.

`/cha-init` 은 **관문을 짐작하지 않습니다.** `package.json` · `Makefile` · `pyproject.toml` · `Cargo.toml` 을 읽고 **실제로 있는** 명령만 씁니다. 없는 `npm run lint` 를 적어 두면, 그 관문은 돌아가는 척하면서 아무것도 안 막습니다. 하나도 못 찾으면 그렇게 말하고 물어봅니다.

`.cha/record.md` 가 이미 있으면 `/cha-init` 은 **멈춥니다.** 그 저장소는 이미 CHA 아래에 있고, 기록을 덮어쓰는 것이 이 도구가 할 수 있는 제일 나쁜 일입니다.

## 3. `config.json` 채우기

Node 저장소 예시입니다. 키 이름은 도구가 **실제로 읽는** 것이고, 다른 이름을 쓰면 조용히 기본값으로 떨어집니다.

```json
{
  "gate": {
    "test": "npm test",
    "check": "npm run check",
    "docs": "npm run docs"
  },
  "secondEye": {
    "command": "some-cli --model 정확한-모델-id --read-only -p @{file}",
    "model": "정확한-모델-id",
    "mode": "read-only",
    "maxRetries": 6,
    "backoffMs": 1200000,
    "timeoutMs": 600000
  },
  "briefing": { "maxBytes": 20480 },
  "mutate": {
    "testCommand": "node {file}",
    "copy": ["src", "test", "bin", "lib", "docs", "tools", "package.json"],
    "timeoutMs": 180000
  },
  "writer": "claude-only"
}
```

### `gate`

이름 → 명령의 짝입니다. 개수는 자유고, `/cha-gate` 가 **적힌 순서대로 전부** 돌립니다.

규칙 하나: **안 돌려 본 명령은 안 적습니다.** 관문에 이름만 있고 실행이 안 되는 명령이 있으면, 그 자리는 초록도 빨강도 아닌 채로 초록으로 보고됩니다.

### `secondEye.command`

셸 틀입니다. **`tools/queue.mjs` 가 바꿔 주는 것은 `{file}` 하나뿐**이고, 그 자리에 브리핑 경로가 들어갑니다. 나머지는 손대지 않으니 모델 id 는 글자 그대로 적습니다.

```
"command": "some-cli --model 정확한-모델-id --read-only -p @{file}"
```

여기에 `{model}` 이라고 적으면 **안 바뀝니다.** `{model}` 이라는 일곱 글자가 그대로 CLI 로 넘어가고, 그다음은 그 CLI 에 달렸습니다 — 나은 쪽은 오류를 내고, 나쁜 쪽은 자기 기본 모델로 조용히 떨어져서 **고르지도 않았고 나중에 확인할 수도 없는 모델**로 검토합니다. id 는 두 군데에 적습니다. 명령에 한 번, 기록이 인용할 수 있게 `secondEye.model` 에 한 번.

**틀에 `{file}` 이 없으면** 브리핑을 stdin 으로 밀어 넣습니다. 그러니 파일 인자를 안 받는 CLI 도 됩니다.

```
"command": "some-cli --model 정확한-모델-id --read-only"
```

`null` 로 두면 `/cha-review2` 가 멈추고 [05 — 2차 눈](05-2차눈.md) 을 가리킵니다. **자기 자신으로 대신 검토하고 2차 눈이라고 부르지 않습니다.** 그건 [00 — 왜](00-왜.md) 에서 말한 상관된 오류 그대로입니다.

### `secondEye.model`

**정확한 모델 id.** `latest` · `default` · 빈 값 금지.

`latest` 는 말없이 바뀝니다. 바뀐 날 회차 38과 회차 39의 숫자는 서로 비교할 수 없는 것이 되고, 그걸 알아채는 방법이 없습니다. `tools/queue.mjs` 는 이 값이 비어 있으면 경고를 찍고 계속합니다 — 멈추지는 않지만, 경고가 나온 회차의 숫자는 다음 회차와 나란히 못 놓습니다.

### `secondEye.mode`

`"read-only"`. 2차 눈에는 쓰기 도구도 셸도 저장소 접근도 안 줍니다. 브리핑 글만 줍니다.

고칠 수 있는 검토자는 **두 번째 쓰는 곳**이고, 반만 붙은 고침은 거기서 나옵니다.

### 한도 관련 셋

| 키 | 기본값 | 무엇 |
|---|---|---|
| `maxRetries` | 6 | 같은 브리핑을 다시 물어볼 최대 횟수 |
| `backoffMs` | 1200000 (20분) | 한도에 걸렸을 때 자는 시간 |
| `timeoutMs` | 600000 (10분) | 한 판의 제한 시간 |

`tools/queue.mjs` 는 한도에 걸리면 **건너뛰지 않고 같은 브리핑을 다시 묻습니다.** 넘어가면 그 조각은 아무도 안 본 채로 검수가 끝나고, 개수만 맞습니다.

병렬은 안 씁니다. 세 판을 한꺼번에 보냈다가 개인 한도가 **4분 만에 비었고 답 셋을 전부 잃었습니다** — 세 판이 각자 제 재시도 루프를 돌렸기 때문입니다.

### `briefing.maxBytes`

기본 `20480`. **줄이 아니라 바이트**입니다. 한글은 글자당 3바이트라서 줄 수로 재면 한국어 브리핑이 영어 브리핑의 세 배 크기로 나갑니다.

왜 20KB 인지, 그 위에서 무엇이 조용히 깨지는지는 [04 — 브리핑](04-브리핑.md) 과 [03 — 하네스 조정](03-하네스조정.md).

### `mutate.testCommand`

**검사 파일 하나**를 돌리는 명령입니다. `{file}` 이 일터 안의 경로로 바뀝니다.

| 도구 | 값 |
|---|---|
| node | `"node {file}"` |
| vitest | `"npx vitest run {file}"` |
| jest | `"npx jest {file}"` |
| pytest | `"python -m pytest {file}"` |

전체 검사를 돌리는 명령을 넣으면 안 됩니다. 어긋 하나마다 이게 한 번씩 돕니다.

### `mutate.copy`

어긋내기는 **소스를 제자리에서 안 망가뜨립니다.** 임시 디렉터리로 베껴 놓고 거기서만 씁니다. Ctrl+C 나 프로세스를 통째로 죽이는 검사가 일부러 망가뜨린 파일을 디스크에 남기면, 그걸 커밋하는 것이 이 도구가 막는 어떤 것보다 나쁩니다.

`copy` 는 **검사가 실제로 돌 수 있을 만큼** 담아야 합니다. 빠진 게 있으면 검사는 빨개지고, 어긋은 「잡음」으로 세어집니다 — 어긋 때문이 아니라 파일이 없어서.

pytest 저장소면 보통 이렇습니다.

```json
"copy": ["src", "tests", "pyproject.toml", "setup.cfg", "conftest.py"]
```

### `writer`

`"claude-only"`. 코드를 쓰는 곳이 하나라는 것을 설정에 적어 둡니다. → [06 — 판정](06-판정.md) · `/cha-fix`

---

## 4. `.gitignore`

```gitignore
.cha/briefings/
.cha/answers/
```

`record.md` 와 `mutants.json` 은 **추적합니다.** 그 둘이 결과물입니다. 중간에 만들어진 브리핑과 답은 아닙니다.

---

## 5. 훅

`hooks/hooks.json` 에 `PostToolUse` 훅이 하나 들어 있습니다. `Edit` 이나 `Write` 로 소스 파일을 고치면, 그 저장소에 `.cha/` 가 있을 때만, 「이 고침에는 빨간 검사와 어긋이 필요하다」 고 한 줄 알려 줍니다.

**절대 안 막습니다.** 언제나 0 으로 끝나고, 입력을 못 읽으면 조용히 0 으로 끝납니다. 남의 작업을 끊는 훅은 없는 훅보다 나쁩니다.

## 6. 2차 플랫폼이 없다면

솔직하게 적습니다. **값이 많이 떨어집니다.** 전부의 요점이 상관되지 않은 오류인데, 그 자리가 비면 남는 것은 절차뿐입니다.

쓸모 있는 순서대로:

**(a) 다른 회사의 무료 등급.** 제일 낫습니다. 학습이 다르고 실패 방식이 다릅니다. 한도가 좁아도 괜찮습니다 — `queue.mjs` 가 한도를 알고 기다립니다. 회차를 하루에 걸쳐 돌리는 것은 문제가 아닙니다.

**(b) Ollama 로 돌리는 로컬 모델.** 약합니다. 지적을 덜 찾고 거짓 지적을 더 냅니다. 그래도 **학습이 진짜로 다릅니다.** 거짓 지적은 판정에서 걸러지니까, 약한 쪽은 감당할 수 있는 비용입니다. 상관된 쪽은 아닙니다.

**(c) 사람.** 느리고 좁지만 사각지대가 완전히 다릅니다. 브리핑을 20KB 로 자른 것이 여기서 그대로 쓸모 있습니다 — 사람도 400줄짜리 답은 못 냅니다.

**(d) 마지막 수단: 3번 걸음을 빼고 돈다.** 1·2 로 의심을 만들고, 4번부터 9번까지 그대로 돌립니다. 이렇게만 해도 빨간 검사 먼저 · 어긋 · 누적 기록은 남고, 그 셋만으로도 값이 있습니다.

그런데 이건 **주 장기를 뺀 CHA** 입니다. 남은 것은 규율이지 적대성이 아닙니다. 그렇게 부르지 마세요. 스스로에게도.

## 7. 시작 전에 관문이 초록인지 본다

루프를 돌리기 전에 관문 명령을 한 번씩 돌립니다.

```
/cha-gate
```

**빨간 상태에서 시작한 루프는 제가 망가뜨린 것과 원래 망가져 있던 것을 구분하지 못합니다.** 회차 중간에 검사가 빨개졌을 때 「방금 고친 것 때문인가, 원래 그랬나」 를 물어야 한다면, 그 회차의 판정은 전부 흔들립니다.

`/cha-gate` 는 단어가 아니라 숫자를 냅니다 — 통과 · 실패 · 건너뜀, 그리고 **검사 파일 몇 개가 정상으로 끝났는가**. 마지막 것이 빠지면 관문이 거꾸로 움직입니다. 파일 여섯이 아무것도 못 물어보고 죽으면 통과 개수가 **늘어납니다.**
